# When you outgrow the browser

## Three signs it is time [0:00]

There are a few signs that it might be time to move beyond a browser-based builder. First, some users report that these builders may not retain context effectively. You might find yourself describing the same project details over and over. Second, you may want to use a specific library or an unusual integration that the builder doesn’t support. Lastly, if you need to collaborate with someone else, that can be tough in a browser environment. None of these points are about difficulty. They’re more about ownership and control over your project.


## What actually changes [0:35]

When you transition, your project moves from being inside a builder to existing as actual files on your computer. This change gives you more control. You can store those files safely, share them with a developer, or even switch to a different tool if you want. None of that is possible when you’re working within a browser-based builder. The trade-off? You’ll need to deal with some setup — things like installations, a terminal, and a few new terms to learn.


## What an AI coding agent is doing [1:05]

Now, let's talk about what an AI coding agent actually does. It’s not just autocomplete or a chat window that knows code. When you give it a request, it looks through your project for relevant information. Then, it decides which files to change, makes those edits, and can even run the project to check if everything works. That last part is crucial. It verifies its own work, which can save you a lot of headaches down the line.


## Watch it happen on a real project [1:34]

Next, let’s see this in action. What follows is a genuine recording of an AI coding agent at work. Nothing is staged, and you’ll see everything as it happens. We’ll use the habit tracker project from lesson three, which has been exported to files. The request will be to add a weekly summary feature, which touches multiple parts of the project. This is where a builder might struggle, but an agent can really help. Watch what it does.


## Reading what just happened [2:02]

After the agent completes its task, it looks at the project before making any changes. That’s why it can place new code in the right spot instead of creating a new file. It often changes more than one file because features usually involve multiple parts of a project. Plus, it provides a summary of what it did. Make sure to read that part. It’s your only record of what changed if you don’t check the files yourself.


## The habits that keep this safe [2:30]

To keep your project safe, start using version control from day one. This is something we’ll cover in lesson nine, and it’s what makes features like 'undo everything since Tuesday' possible. Also, take a moment to read the summary of changes, even if you don’t dive into the code. If there’s something you don’t understand, ask the agent for an explanation. There are no stupid questions here, and the explanation is part of the process.
